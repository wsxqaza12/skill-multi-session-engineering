# 派工 brief 範本（實作 worker）

把下面整份複製進 dispatch 資料夾的 `prompt.md`，每一節都要填。用 `<<'EOF'` 寫檔，反引號才不會被 shell 執行。

```markdown
# 任務：<一句話>

## 位置
- repo／worktree：<完整絕對路徑>
- branch：<名稱>，base commit：<完整 SHA>
- 同時在做、可能碰到同一批檔案的工作：<列出；沒有就寫「無」>
- 輸出寫到：<完整絕對路徑>（不准寫相對路徑或「上一個資料夾」）

## 要做什麼
- 規格出處：<檔案:行號／設計文件／D-xx>
- 已經定案的範圍：<條列>
- 行為要照抄規格原文：<把關鍵句子原文貼上>

## 不准做的事（must not）
- 不改 <列出不在範圍內的檔案或模組>
- 不改既有測試的邏輯（斷言、過濾、參數）；要改就停下來回報 file:line
- 不連網、不讀或印出金鑰、不寫本機路徑或私有名稱到 repo
- 不要讀固定的 commit（git archive／show 某個 SHA）當測試基準；CI 是淺 clone。需要跟 base 比對時，寫成獨立的比對腳本，不進 CI
- 規格和程式衝突時停下來回報 file:line，不要自己重新詮釋

## 測試
- 要跑的 runtime 版本：<例如 Node 22 和 24>
- 推導測試清單，不能用手挑：
  1. 改到的模組，所有 import 它的檔案（含間接）；
  2. 所有提到改到的函式或字串的測試；
  3. 所有靜態閘門：census、hash 釘、split、成本、事件時間、打包清單。
- 回報「N 個／共 M 個」和每個檔案的**真實 exit code**（`cmd; rc=$?`，不要接 `| tail`）。
- 本機跳過、只在 CI 跑的測試要另外列出來。
- 測試裡寫死的數值（hash、計數、清單）一律**先交給主控核准再 commit**。

## 交付
- 改了哪些檔案：用兩種方法交叉核對（`git diff --name-only` 和 `git status`），列出數量
- 建立的暫存資料夾要在結束時刪掉，並回報有沒有留下東西
- 最後寫 `last.md`：做了什麼、測試結果、還沒做的、遇到的問題
```

**主控派工前自己檢查：**
- dispatch 資料夾是新的，不存在才建立。
- 已經掛上 `wait-any-worker.sh <名稱>`。
- 環境裡的金鑰都列進了 `DISPATCH_UNSET_ENV`。

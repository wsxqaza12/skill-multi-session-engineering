# 發版

1. **切版前，重查所有還沒關的已知問題**，對照的是實際要切版的 base，用 `git merge-base --is-ancestor` 加上看程式碼確認。記在別的版本名下的問題，換分支切版後不會自動消失。
2. **修正輪只修**：新行為等下一版。
3. **對外文字**（README、CHANGELOG、說明）：
   - 每個數字都附出處：哪一次量測、哪台機器、單次還是百分位；
   - 有測試把關鍵句子釘住，換掉的舊說法也要釘住「不能再出現」；
   - 寫清楚沒有金鑰時哪些功能比較弱；
   - 預設開啟的功能，要附關閉的方法。
4. **實機測試要及早跑**，用真的 client 和真實格式的資料：
   - 測試用的家目錄要用完就丟，不碰使用者真正的設定；
   - 回報只寫版本、exit code、數量、是／否，不貼對話內容。
5. **要發佈的檔案**，跟實測過的那份要逐檔比對 sha256，一致才算數。
6. **發佈由 owner 親手做**（OTP、「發」）。主控把 desk 上的題目準備好，owner 在 desk 上核准。
7. **發佈後**：核對 registry 上的 integrity，再打 annotated tag、建 release。GitHub release 的「latest」旗標要用 API 確認一次。

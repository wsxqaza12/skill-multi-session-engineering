# 合併前檢查表（主控）

每一項都要真的看過，不能用印象。結果記進 desk 日誌。

## 推導測試清單（推之前做）
1. **用兩種方法推導，再取聯集：**
   - A：改到的模組，所有 import 它的檔案（含間接）；
   - B：所有提到改到的函式或字串的測試（`grep`）。
   - 推導時別漏了這些位置：`scripts/`、`docs/`、`public/`、設定檔和打包清單。
2. **兩種方法都推不到、但會受影響的**：靜態閘門、hash 釘、census、成本、事件時間、打包清單。
3. **全部跑完**，回報「N 個／共 M 個」和每個檔案的 exit code。本機跳過、只在 CI 跑的，另外列出來。
4. 不說「全套都過了」，要說「受影響清單 N/M 都過了」。

## 合併前
- [ ] **CI 每個 job 都看過結論**：failure 和 cancelled 分開看；skipped 不等於通過；被 fail-fast 取消的要重跑；因為「沒有 runner」被取消的（例如 macOS）不算失敗也不算通過，重跑到有真正的結論。
- [ ] **head 跟最新的 main 同步**。main 有保護規則時，任何合併都會讓其他 PR 重跑 CI，所以要排好順序。
- [ ] **審查結論讀審查員的最後一則訊息**（`last.md` 的 `VERDICT:` 行和第一行的範圍），確認審的就是現在這個 head。不是的話，逐檔比對 patch-id。
- [ ] **寫死的數值**（hash、計數、清單）commit 前主控核准過；沒核准的不能出現在 diff 裡。
- [ ] **有沒有改到既有測試的邏輯或 fixture**（斷言、預期值、訊息、迴圈、import）：有的話，合併前一定要有 owner 本人的放行紀錄。gate owner 不能代替放行，主控只核准生成的數值。
- [ ] **一次非作者審查**：修正後的確認交回同一位審查員，只看修正的 diff（見 `review-brief.md`）。
- [ ] **公開掃描**：diff、commit 訊息、PR 內文、打包產物裡，不能有本機路徑、金鑰、私有名稱、內部編號、正式環境的精確數字。
- [ ] **用到模型的功能**：合併前真的跑過一次真模型，數「被接受的輸出」和「預設讀取裡真的出現的項目」。
- [ ] **跟規模有關的**（索引、新鮮度、清理）：用真實大小證明它跑得完。
- [ ] **改到對外的介面或輸出形狀**：跑過多版本相容測試，也查過對方的驗證器和白名單。
- [ ] **新模組**：靜態閘門、打包清單、不載入 SQLite 的那條路徑都登記了。
- [ ] **合併就等於發佈的**（例如外掛的 marketplace 直接讀 main）：先跑一次真 client 的煙霧測試，再取得 owner 明確的「發」。
- [ ] 用 `--match-head-commit <SHA>` 合併，再看合併後 main 的 CI。
